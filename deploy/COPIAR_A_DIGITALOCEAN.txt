================================================================================
  DIGITALOCEAN APP PLATFORM — Variables para el WEB SERVICE (PostgreSQL)
================================================================================

No puedo darte contraseñas reales: salen SOLO de tu cuenta en DigitalOcean.
Ruta: Menú "Databases" → elige tu clúster PostgreSQL → pestaña "Connection details"
       (o "Connection parameters").

Copia host, puerto, usuario, contraseña y nombre de base. Suele ser:
  - Usuario: doadmin
  - Base: defaultdb  (o la que creaste)
  - Puerto: 25060 u otro (NO 5432 en bases administradas)
  - Host: algo como db-postgresql-xxxxx-do-user-xxxxx-0.db.ondigitalocean.com
  - SSL: obligatorio → sslmode=require

En la APP: Apps → tu aplicación → Settings → Components → [Web Service] → Edit
→ Environment Variables → añade las variables abajo (Scope: Run time).

IMPORTANTE: La consola "Console" de App Platform debe ser del MISMO Web Service que
ejecuta Gunicorn, para que DATABASE_URL sea la misma que ve el navegador al guardar.
Si compara con su PC, el HOST del Postgres puede ser otro clúster (números distintos
en el hostname) y verá 0 filas aunque la web "guarde" en otro sitio.

--------------------------------------------------------------------------------
OPCIÓN A — Una sola variable (recomendada): DATABASE_URL
--------------------------------------------------------------------------------

Formato (sustituye los valores entre < > por los del panel, sin espacios extra):

  DATABASE_URL=postgresql://<USUARIO>:<CONTRASEÑA>@<HOST>:<PUERTO>/<NOMBRE_BD>?sslmode=require

Ejemplo de forma (NO es real, solo estructura):

  DATABASE_URL=postgresql://doadmin:miClaveSecreta@db-postgresql-nyc3-12345-do-user-99-0.db.ondigitalocean.com:25060/defaultdb?sslmode=require

Si la contraseña tiene caracteres especiales (@ # : etc.), en el panel de DO suele
darte la URI ya codificada; úsala tal cual o codifica la contraseña en la URL.

--------------------------------------------------------------------------------
OPCIÓN B — Variables separadas (mismo efecto que OPCIÓN A)
--------------------------------------------------------------------------------

  POSTGRES_DB=defaultdb
  POSTGRES_USER=doadmin
  POSTGRES_PASSWORD=<PEGAR_CONTRASEÑA_DEL_PANEL>
  POSTGRES_HOST=<PEGAR_HOST_DEL_PANEL>
  POSTGRES_PORT=25060
  POSTGRES_SSLMODE=require

(Ajusta POSTGRES_DB si tu base tiene otro nombre.)

--------------------------------------------------------------------------------
Otras variables útiles para la misma app (Web Service)
--------------------------------------------------------------------------------

  DEBUG=False
  SECRET_KEY=<generar cadena larga aleatoria>
  DJANGO_CSRF_TRUSTED_ORIGINS=https://plankton-app-pik7q.ondigitalocean.app
  PUBLIC_BASE_URL=https://plankton-app-pik7q.ondigitalocean.app

(Sustituye la URL si tu app tiene otro nombre en *.ondigitalocean.app)

--------------------------------------------------------------------------------
Media persistente (PDFs, planos) — DigitalOcean Spaces + django-storages
--------------------------------------------------------------------------------

Sin esto, cada redeploy borra la carpeta media del contenedor y fallan descargas de PDFs viejos
(aunque la BD siga apuntando al archivo). Lo mismo afecta las FIRMAS del "Formato de aceptación":
si `verificar_formatos_aceptacion` muestra "BD tiene ruta pero NO existe en storage", necesita
Spaces (abajo) y luego volver a firmar en el formulario.

Cree un Space, genere una "Spaces access key" y añada:

  DJANGO_USE_S3_MEDIA=1
  AWS_ACCESS_KEY_ID=<key>
  AWS_SECRET_ACCESS_KEY=<secret>
  AWS_STORAGE_BUCKET_NAME=<nombre_del_space>
  AWS_S3_REGION_NAME=nyc3
  AWS_S3_ENDPOINT_URL=https://nyc3.digitaloceanspaces.com

(Ajuste región y endpoint a la de su Space: fra1, sfo3, etc.)

Opcional: AWS_S3_CUSTOM_DOMAIN=... si usa CDN. Detalle en .env.example del repo.

--------------------------------------------------------------------------------
Si aparece: password authentication failed for user "doadmin"
--------------------------------------------------------------------------------

La red y el host suelen estar bien; el servidor rechaza la clave que recibe.

1) Deje DATABASE_URL pero añada OTRA variable (secreto) con la clave exacta del panel:
      POSTGRES_PASSWORD=<misma clave que en DigitalOcean, sin comillas>
   El proyecto usará esa variable en lugar de la contraseña incrustada en la URL
   (útil si al copiar la URI se truncó o hubo un carácter raro).

2) O bien BORRE DATABASE_URL y use solo la OPCIÓN B (variables sueltas), pegando la
   contraseña solo en POSTGRES_PASSWORD.

3) Revise que no queden variables viejas con otra contraseña en el mismo Web Service.

4) En el panel, "Encrypt" / tipo SECRET para la contraseña; sin espacios al inicio o final.

--------------------------------------------------------------------------------
Recibos: correo con PDF y WhatsApp
--------------------------------------------------------------------------------

IMPORTANTE: el archivo ".env" en su PC NO se sube a Git ni a DigitalOcean.
  Copie manualmente las mismas variables al Web Service → Environment.

CORREO
  Sin variables SMTP, Django usa "consola": el PDF no llega al cliente (solo log).
  En el Web Service añada, según su proveedor (Gmail, Office365, hosting, etc.):
    EMAIL_HOST=...
    EMAIL_PORT=587
    EMAIL_USE_TLS=True
    EMAIL_USE_SSL=False
    EMAIL_HOST_USER=...
    EMAIL_HOST_PASSWORD=...
    DEFAULT_FROM_EMAIL=...   (suele ser el mismo correo que EMAIL_HOST_USER)
  Vea .env.example para más ejemplos.

WHATSAPP
  El botón "Abrir WhatsApp" usa wa.me: solo abre el chat con TEXTO; no adjunta PDF
  (así funciona WhatsApp, no es un fallo del sistema).
  Opciones para enviar el PDF como documento:
    - Meta WhatsApp Cloud API: WHATSAPP_CLOUD_ENABLED=1, RECIBO_ENVIAR_WHATSAPP_META=1,
      token, PHONE_NUMBER_ID, etc. (ver .env.example)
    - Twilio: RECIBO_ENVIAR_WHATSAPP_TWILIO=1 y credenciales; PUBLIC_BASE_URL en HTTPS
      para la URL del PDF si aplica.

  Enlace al PDF dentro del mensaje de wa.me (recomendado si no usa Meta/Twilio):
    PUBLIC_BASE_URL=https://su-app.ondigitalocean.app
    DJANGO_SERVE_MEDIA_PUBLIC=1
  Sin la segunda variable, en producción (DEBUG=False) la ruta /media/... da 404
  aunque PUBLIC_BASE_URL esté bien. Implica PDF bajo /media/ accesibles sin login.

--------------------------------------------------------------------------------
ERROR: relation "inmobiliaria_formatoaceptacion" does not exist (u otra tabla)
--------------------------------------------------------------------------------

La base de datos en DigitalOcean no tiene las migraciones aplicadas.

1) Consola del Web Service → ejecute:
     python manage.py migrate --noinput

2) Para que no vuelva a pasar: en el componente Web → Settings → Run Command debe
   ejecutar migrate ANTES de gunicorn, por ejemplo (una sola línea):

     python manage.py migrate --noinput && gunicorn backend.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --threads 2 --timeout 120 --access-logfile - --error-logfile -

   (El Procfile del repo ya usa ese patrón si su plataforma lo respeta al desplegar.)

--------------------------------------------------------------------------------
ERROR: column ... promesa_venta_escaneada does not exist
--------------------------------------------------------------------------------

El código ya incluye el campo en el modelo pero la base de datos no tiene la migración
0024 (o superior). Solución: en la consola del Web Service ejecute de inmediato:

  python manage.py migrate --noinput

En App Platform, el Run Command recomendado es usar el script del repo (migra y arranca):

  bash scripts/run_web.sh

No use solo "gunicorn ..." sin migrate, o tras cada despliegue con modelos nuevos
volverá a faltar una columna o tabla.

--------------------------------------------------------------------------------
Después de guardar y desplegar
--------------------------------------------------------------------------------

En la consola del Web Service (Console):

  python manage.py migrate --noinput
  python manage.py createsuperuser

En el clúster PostgreSQL: "Trusted sources" debe permitir conexiones desde App Platform.

Validación en tu PC (con .env ya configurado):

  python manage.py validate_digitalocean --as-app-platform --try-connect
